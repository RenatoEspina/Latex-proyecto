\chapter{Diagramas de secuencia y colaboración}
\label{cap:interaccion}

Se presentan los diagramas de secuencia y de colaboración de cuatro casos de uso considerados los
más relevantes del sistema: importar el manifiesto, crear una programación, registrar el
desconsolidado en terreno y revisar el reporte. Ambos tipos de diagrama describen la misma
interacción: el de secuencia enfatiza el orden temporal de los mensajes y permite representar
condiciones y repeticiones, mientras que el de colaboración enfatiza qué objetos se relacionan
entre sí.

Los diagramas se construyeron como \textbf{diagramas de secuencia del sistema}
\parencite{larman2003}: el sistema se representa como una caja negra (\clase{:Sistema BeeTracer}
en la plataforma web y \clase{:App BeeTracer} en la aplicación móvil) que recibe los
\textbf{eventos del sistema} generados por los actores y se comunica con los servicios externos
(\clase{:ServicioAduana}, \clase{:ServicioCorreo}) y con la base de datos local del dispositivo
(\clase{:Base de Datos}). La Tabla~\ref{tab:eventos_operaciones} relaciona cada evento del
sistema con las operaciones del diagrama de clases (Capítulo~\ref{cap:clases}) que lo resuelven
en el diseño.

\section{Diagramas de secuencia}
\label{sec:secuencia}

Los diagramas de secuencia utilizan fragmentos combinados para representar las decisiones
(\texttt{alt}), las acciones opcionales (\texttt{opt}) y las repeticiones (\texttt{loop}) que
aparecen en los cursos alternos de los casos de uso narrativos.

\subsection{Importar manifiesto}
\label{subsec:sec_manifiesto}

El Jefe de faena solicita la importación del manifiesto de una nave y viaje. El sistema solicita
el XML a \clase{:ServicioAduana} y, si el XML es válido y el servicio está en línea, guarda los
contenedores y lotes declarados y confirma la importación; en caso contrario muestra un error
(curso normal y cursos A1 a A3 de la Tabla~\ref{tab:cu_importar_manifiesto}).

{Diagrama de secuencia - Importar manifiesto}
{Diagrama de secuencia - Importar manifiesto.}
{fig:sec_manifiesto}

\subsection{Crear programación}
\label{subsec:sec_programacion}

El Jefe de faena crea la programación de un contenedor indicando fecha y hora. El sistema verifica
la disponibilidad del horario; si no hay conflictos de agenda, el Jefe de faena asigna la cuadrilla
y el jefe tarjador, y el sistema verifica la disponibilidad del personal antes de guardar la
programación. Si hay conflictos, alerta la indisponibilidad (Tabla~\ref{tab:cu_crear_programacion}).

\figuradiagrama{0.72}{14-sec-crear-programacion.jpg}
{Diagrama de secuencia - Crear programación}
{Diagrama de secuencia - Crear programación.}
{fig:sec_programacion}

\subsection{Registrar desconsolidado}
\label{subsec:sec_operacion}

Corresponde al caso de uso \textit{Registrar datos de operación}. El Jefe tarjador inicia la
faena desde la aplicación móvil y, por cada lote de cliente (repetición), registra la cantidad y
su fotografía, que la aplicación guarda en la base de datos local; si hay daño o diferencia
(opción), registra además una incidencia con sus fotografías. Al finalizar la faena con la
fotografía del contenedor vacío, la aplicación sincroniza los datos con el servidor y confirma el
cierre (Tabla~\ref{tab:cu_registrar_datos}).

\figuradiagrama{0.80}{15-sec-registrar-desconsolidado.jpg}
{Diagrama de secuencia - Registrar desconsolidado}
{Diagrama de secuencia - Registrar desconsolidado.}
{fig:sec_operacion}

\subsection{Revisar reporte}
\label{subsec:sec_reporte}

Corresponde al caso de uso \textit{Validar reporte}. El Supervisor revisa el reporte y el sistema
le muestra los datos y fotografías. Si los datos y la evidencia son correctos, el Supervisor lo
aprueba y el sistema envía el PDF al cliente mediante \clase{:ServicioCorreo}; si la evidencia es
defectuosa, rechaza la fotografía indicando el motivo, el reporte pasa a estado «En Corrección» y
se notifica la solicitud de recaptura a terreno (Tabla~\ref{tab:cu_validar_reporte}).

\section{Diagramas de colaboración}
\label{sec:colaboracion}

Como complemento, se presentan los diagramas de colaboración de los mismos cuatro casos de uso,
con los mismos objetos y mensajes que sus diagramas de secuencia. En ellos los mensajes se numeran
para indicar el orden, y la numeración decimal (por ejemplo, 2.1) indica que el mensaje se origina
como consecuencia del mensaje 2; el asterisco indica una repetición y la condición entre corchetes,
una guarda. Las flechas \(\downarrow\) y \(\uparrow\) junto a cada mensaje indican su sentido
(hacia el objeto de abajo o de vuelta hacia el de arriba). Se muestra el curso normal de cada caso, incluyendo las repeticiones necesarias, y se
omiten los cursos alternos, que ya se detallan en los diagramas de secuencia.
